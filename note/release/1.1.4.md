# 1.1.4 — 逻辑闭合、稳定性与安全性修复

> 基于分支 `adapt/build-1.21.11`（适配 1.21.11 进行中），在 1.1.3 基础上的修复版本。
> 目标：逻辑闭合、长时间高负载/多用户高频使用下的稳定性，以及面对不可信用户输入
> （客户端可篡改发送数据）的安全性。所有修复均已通过 `mvn clean package -DskipTests`。

## 修复清单（按影响分级）

### 🔴 数据操作 / 刷物品（严重）

1. **工作站「幽灵堆」刷物品漏洞** — [GastroWorkstation.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/manual/GastroWorkstation.java) / [ElectricKitchen.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/automatic/ElectricKitchen.java)
   - 合成耗尽原料时仅把 `ItemStack.amount` 置 0，槽位残留 amount=0 的「幽灵堆」。
   - 配方匹配（`isSimilar`）与缓存哈希（`asOne` / `hashIgnoreAmount`）均忽略数量，
     幽灵堆仍被当作有效原料 → 下次合成空耗产出 → **刷物品**。
   - ElectricKitchen 缓存命中还会复用上次的 `Counter`，同样从幽灵堆空耗产出。
   - 修复：原料/容器耗尽（amount≤0）后显式清空槽位（`setItem(null)` / `replaceExistingItem(slot,null,false)`）。
   - 注：ElectricKitchen 的重新匹配路径本就有 `amount > found.get(slot)` 守卫；清空后哈希变化触发缓存失效，守卫生效。

2. **`/gn proficiency` 修改他人熟练度写错玩家** — [GastroCommandExecutor.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/command/GastroCommandExecutor.java)
   - `commandProficiencyModify` 使用操作者 `player.getUniqueId()` 而非目标 `other`，
     管理员修改他人熟练度实际改了自己的档案。改用 `other.getUniqueId()`。

3. **查看他人档案显示自己的熟练度** — 同上
   - `sendProficiencies(player, toCheck)` 使用了 `player` 而非 `toCheck` 的 UUID。改用 `toCheck`。

4. **`proficiency sub` 模式把熟练度归零** — 同上
   - 误用 `Math.min(current - amount, 0)`，无论当前值多少都被钳到 0。改为 `Math.max(..., 0)`。

### 🟠 并发 / 长期运行稳定性

5. **HuntingTrap 共享 `active` 字段导致整类陷阱失效** — [HuntingTrap.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/manual/HuntingTrap.java)
   - `active` 是「每类物品共享一个 BlockTicker 实例」的实例字段，任一陷阱 `canCatch`
     失败返回 false 会把该类型**所有**陷阱的 active 置 false、永久停止捕获。移除该字段，
     改由 `triggeredTraps` 的 per-block 状态管理。

6. **HuntingTrap / FishingNet 异步线程访问非线程安全 API** — 同上 / [FishingNet.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/automatic/FishingNet.java)
   - 两者的 `BlockTicker.isSynchronized()` 原为 false（异步执行），但 tick 内访问
     World（spawnParticle/getBlockData）、读写 BlockStorage、操作方块库存，且
     HuntingTrap 的 `triggeredTraps`（原 HashMap）被异步 ticker 与主线程处理器并发访问。
   - 修复：两者 `isSynchronized()` 改 true；HuntingTrap 的 Map 改为 `ConcurrentHashMap`。

6b. **ElectricKitchen 静态缓存并发访问** — [ElectricKitchen.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/automatic/ElectricKitchen.java)
   - `AContainer.isSynchronized()` 返回 false，ElectricKitchen 的 tick 运行在 Slimefun
     TickerTask 的**异步线程**上，而 `onBlockBreak`（`SimpleBlockBreakHandler`）在主线程；
     二者并发读写静态缓存 `lastInputHashAndRecipe`（HashMap），高负载多电厨下存在
     并发 put/remove 丢条目/损坏风险。改为 `ConcurrentHashMap`。

7. **GastroWorkstation.onBreak 配置缓存内存泄漏** — [GastroWorkstation.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/manual/GastroWorkstation.java)
   - 破坏工作站时未从静态缓存 `lastInputHashAndRecipe` 移除该方块条目（ElectricKitchen 有移除），
     长期放置/破坏会造成内存泄漏。补上 `remove`。

8. **TreeStructure 启动期 NPE** — [TreeStructure.java](../../src/main/java/io/github/schntgaispock/gastronomicon/api/trees/TreeStructure.java)
   - 全新安装时 `plugins/Gastronomicon/schematics/` 不存在，`listFiles()` 返回 null → NPE → 插件启动失败。
   - 修复：先 `mkdirs()` 并判空；并从 jar 内置资源解包 schematic，保证全新安装也能加载；
     单文件解析失败不再中断整体加载。

### 🟡 逻辑缺陷 / 配置未生效

9. **`MILK_BUCKET` 误用 `WATER_BUCKET`** — [ItemSetup.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/setup/ItemSetup.java)
   - `MILK_BUCKET` 常量被赋值为 `Material.WATER_BUCKET`，导致约 40 个配方（奶黄、冰淇淋、
     浓汤、面包、奶茶等）实际要求输入水桶。改为 `Material.MILK_BUCKET`。

10. **`GroupRecipeComponent.matches` 只匹配组内首个元素** — [GroupRecipeComponent.java](../../src/main/java/io/github/schntgaispock/gastronomicon/api/recipes/components/GroupRecipeComponent.java)
    - 循环在首次迭代即 return，导致组配方只能匹配 Set 中碰巧排第一的物品，其余永不匹配
      （Set 顺序不确定，表现为组配方偶发失效）。改为遍历全部、命中任一即返回 true。
    - 同步加固 `getDisplayItem`（lore 可能为 null、空组 `findFirst()` 抛异常）。

11. **`perfect-food-max-chance` 配置项从未被读取** — [GastroWorkstation.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/manual/GastroWorkstation.java)
    - 完美食物概率上限硬编码 0.25，config 修改不生效。改为读取配置并钳制到 [0,1]，
      避免误配 >1 时 `randomRound` 返回 ≥2 越界取到产物数组的返还槽位。

12. **FoodEffect 多处缺陷** — [FoodEffect.java](../../src/main/java/io/github/schntgaispock/gastronomicon/api/food/FoodEffect.java)
    - `giveItem(item, amount)`：创建了带正确数量的 clone 却传入原始 item，amount 被忽略。改传 clone。
    - `_giveItem`：apply 始终给予普通数量，完美食物的 ×1.5 加成仅在描述显示、实际未生效。按 isPerfect 给予。
    - `move()`：`velocity.multiply()` 原地修改并返回同一引用 → `pv==velocity`，普通食物也获得完美倍率、且污染调用方 Vector。改为各自 clone。
    - `clearPotionEffects`：原通过控制台 `dispatchCommand("/effect <玩家> clear")`，依赖原版命令且有开销；改为直接遍历移除。

### 🟢 健壮性

13. **TreeStructure.build 缺少对 schematic 的边界校验** — [TreeStructure.java](../../src/main/java/io/github/schntgaispock/gastronomicon/api/trees/TreeStructure.java)
    - schematic 来自磁盘（可被任意修改/损坏），原直接 `palette[id-2]`、`Material.valueOf`，越界/非法材质会抛异常中断生成。增加结构/root/palette 完整性与逐层 null 校验、palette 下标校验，`Material.matchMaterial` 取代 `valueOf`。

14. **ChunkPDC.remove 未持久化** — [ChunkPDC.java](../../src/main/java/io/github/schntgaispock/gastronomicon/util/ChunkPDC.java)
    - 仅从 `getJsonObject` 返回值上 remove 而未 `setJsonObject` 回写，删除不落盘（发酵机破坏后残留脏数据）。改为与 `set()` 一致地 get-modify-set 回写。

15. **MultiStove 温度按钮点击解析易抛异常** — [MultiStove.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/manual/MultiStove.java)
    - 直接 `split(...)[1]` 在显示名异常时 AIOOBE、`fromText` 抛 IAE。增加 hasItemMeta/分段长度校验与异常捕获。

16. **SimpleGastroFood 工具展示越界** — [SimpleGastroFood.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/food/SimpleGastroFood.java)
    - 工具数量 ≥9 时 `display[2+2*i]` 越界（数组仅 18 格）。限制最多展示 7 个工具。

17. **SimpleSapling 每次启动覆盖树木 schematic** — [SimpleSapling.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/seeds/SimpleSapling.java)
    - 构造期 `saveResource(..., true)` 每次启动都覆盖磁盘 schematic，会抹掉服务器管理员对
      树木结构文件的自定义修改（数据覆盖）。改为 `replace=false`（仅不存在时解包），
      与之配套地移除了 TreeStructure 中重复的解包逻辑（保留目录判空防护）。

### 第三轮补充

18. **LootTable / ItemLootTableBuilder 重复掉落物破坏权重不变量** — [LootTable.java](../../src/main/java/io/github/schntgaispock/gastronomicon/api/loot/LootTable.java) / [ItemLootTableBuilder.java](../../src/main/java/io/github/schntgaispock/gastronomicon/api/loot/ItemLootTableBuilder.java)
    - 同一掉落物重复添加时 `put` 覆盖旧权重而 `totalWeight` 仍累加，使总和不等于表中权重之和，
      破坏 Vose 别名法的概率分布。改为按旧值抵消。当前内置掉落表内无重复项，属潜在隐患。

19. **DynaTech 蜜瓜/哈密瓜配方输出错误** — [DynaTechSetup.java](../../src/main/java/io/github/schntgaispock/gastronomicon/integration/DynaTechSetup.java)
    - 复制粘贴遗留：蜜瓜种子/哈密瓜种子的培育仓产出误写为 `CAULIFLOWER`，应为
      `HONEYDEW_MELON` / `CANTALOUPE`。（DynaTech 默认禁用，仍修正）

20. **VineSeed 返回共享可变掉落列表** — [VineSeed.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/seeds/VineSeed.java)
    - `getHarvestDrops` 返回内部 List 引用且物品未克隆，调用方修改会污染未来掉落。
      改为返回克隆副本，与 SimpleSeed/CropSeed 一致。

### 第四轮补充

21. **ThemedItemStack.getDisplayName 无限递归 → StackOverflowError** — [ThemedItemStack.java](../../src/main/java/io/github/schntgaispock/gastronomicon/api/items/ThemedItemStack.java)
    - 方法内部误调用自身（应为 `super.getDisplayName()`），一旦被调用立即栈溢出。该方法覆盖了
      SlimefunItemStack.getDisplayName()，而 ThemedItemStack 是大量注册物品的基类，粘液科技
      内部/指南展示等任何调用路径都会触发崩溃。改为 super 调用并保留非空回退。

22. **MultiStove 同原料不同温度配方只能命中首个** — [MultiStove.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/manual/MultiStove.java)
    - `findRecipe` 调 `super.findRecipe()`（返回首个原料匹配项）后只校验该单个配方温度；若两份
      MULTI_STOVE 配方原料相同但温度不同，只有先注册的那份会被考虑，温度不符即判「未知配方」。
      改为直接遍历，返回首个「原料匹配 且 温度吻合」的配方。

23. **CollectionUtil.commaJoin 空数组越界** — [CollectionUtil.java](../../src/main/java/io/github/schntgaispock/gastronomicon/util/collections/CollectionUtil.java)
    - 空数组访问 `list[-1]` 抛 AIOOBE。当前无调用方（死代码），作为公开工具方法加固为返回空串。

### 第五轮补充

24. **ElectricKitchen 缺失 REF AContainer 的两道消耗守卫** — [ElectricKitchen.java](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/automatic/ElectricKitchen.java)
    - ElectricKitchen 重写 `findNextRecipe`，但缺失 REF `AContainer#scanForRecipe` 明确具备的两道守卫：
      a. **输出空间检查**：输出满时 REF 不消耗；ElectricKitchen 无此检查 → 原料被消耗、操作完成后产物被 `pushItem` 静默 void（**丢物品**）。现按 `menu.fits` 守卫。
      b. **消耗前重新校验**：ElectricKitchen 异步 tick（`AContainer.isSynchronized=false`）期间玩家可在主线程改动菜单，原消耗循环 `input.asQuantity(...)` 在玩家取走原料时会 **NPE**；原料数量不足时会空耗产出（**可被恶意客户端定时点击利用，少给原料换产物**）。现增加校验循环，任一槽位 null/不足则作废缓存、不消耗、下 tick 重新匹配。
    - 注：FishingNet 无此问题（无输入消耗，void 的是免费产物）；GastroWorkstation/ChefAndroidTrainer 为手动主线程交互、无异步竞态。
