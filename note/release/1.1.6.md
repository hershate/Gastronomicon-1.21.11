# 1.1.6 — 移除全部外部依赖（仅依赖 Slimefun 4.1 + Paper 服务端 API）

> 基于 `fix/remove-guizhanlib-runtime-dep` 分支，在 1.1.5 基础上的**依赖清零**版本。
> 目标：插件除 Slimefun4.1 / Paper 1.21.11 服务端 API 外，**不再有任何外部依赖**。
> 起因：1.1.5 修复 guizhanlib 加载崩溃后，服务端又报 `VerifyError: CustomItemStack is not assignable to ItemStack`
> ——shaded 的 InfinityLib 1.3.9 字节码与 REF Slimefun 4.9.5（`CustomItemStack` 改为 final 工具类）二进制不兼容。

## 问题（1.1.6 起因）

```
java.lang.VerifyError: Bad type on operand stack
  MenuBlock.<clinit> @16: CustomItemStack is not assignable to org.bukkit.inventory.ItemStack
```

shaded 的 InfinityLib 1.3.9 是按**旧版** Slimefun 编译的（彼时 `new CustomItemStack(...)` 返回 `ItemStack`）；
REF 4.9.5 把 `CustomItemStack` 改为 `public final class`（仅静态 `create(...)` 工厂，不再继承 `ItemStack`），
故 InfinityLib 的 `MenuBlock.<clinit>` 把 `CustomItemStack` 赋给 `ItemStack` 静态字段时校验失败。
1.1.5 适配了 Gastronomicon 自身代码，却漏了 shaded 进来的 InfinityLib。

## 修复：移除全部外部依赖

把插件实际用到的极少部分外部库，全部以**源码 vendor**进插件或替换为**服务端自带 API**：

### ① InfinityLib → vendor 为源码（修 VerifyError）
本插件只用 InfinityLib 的 7 个类。取得其源码（`raw.githubusercontent.com`，git/部分网络受阻时改用 web reader），
适配 REF 后 vendor 进插件源码树（保留 `io.github.mooy1.infinitylib` 包名 + 既有 shade 重定向，故插件 import 无需改动）：

| 类 | 处理 |
|---|---|
| [machines/MenuBlock](../../src/main/java/io/github/mooy1/infinitylib/machines/MenuBlock.java) | `new CustomItemStack(...)` → `CustomItemStack.create(...)`（6 处，即 VerifyError 根因） |
| [machines/MenuBlockPreset](../../src/main/java/io/github/mooy1/infinitylib/machines/MenuBlockPreset.java) | 原样（REF 兼容） |
| [groups/SubGroup](../../src/main/java/io/github/mooy1/infinitylib/groups/SubGroup.java)、[MultiGroup](../../src/main/java/io/github/mooy1/infinitylib/groups/MultiGroup.java) | 原样（REF 兼容） |
| [core/AbstractAddon](../../src/main/java/io/github/mooy1/infinitylib/core/AbstractAddon.java) | 精简：去 `GitHubBuildsUpdater`（更新检查）/`AddonCommand`/`Environment`/shade 自检；保留生命周期、`AddonConfig`、`instance/config/log/createKey/slimefunTickCount`、`SlimefunAddon` |
| [core/AddonConfig](../../src/main/java/io/github/mooy1/infinitylib/core/AddonConfig.java) | 去 `Environment`（始终落盘）、`StringUtils.isBlank`→`String.isBlank` |
| [core/PathBuilder](../../src/main/java/io/github/mooy1/infinitylib/core/PathBuilder.java) | 注释保留辅助类（vendor） |

pom 移除 `com.github.SlimefunGuguProject:InfinityLib` 依赖。`slimefunTickCount()`（FishingNet 按 tick 节流复检水浸状态所需）改由 Bukkit 调度器按 `Slimefun.getTickerTask().getTickRate()` 递增。

### ② jackson → GSON（Paper 服务端自带）
[TreeStructure](../../src/main/java/io/github/schntgaispock/gastronomicon/api/trees/TreeStructure.java) 原用 jackson `ObjectMapper`+`@JsonProperty` 读树木 schematic JSON，改为 `com.google.gson`（服务端内置），
用自定义 `JsonDeserializer` 显式调用构造器（保留 `fruitTexture` 派生与 `final` 字段）。[ChunkPDC](../../src/main/java/io/github/schntgaispock/gastronomicon/util/ChunkPDC.java) 本就基于 GSON（经 dough `PersistentDataAPI`），无需改动。pom 移除 jackson-databind / jackson-annotations。

### ③ jsr305 → 移除注解
33 个源文件的 `javax.annotation`（`@Nonnull`/`@Nullable`/`@ParametersAre*`）注解与 import 脚本批量剥离（非功能性元数据，行为不变）。pom 移除 `com.google.code.findbugs:jsr305`。

## 验证

- `mvn clean package -DskipTests` → **BUILD SUCCESS**，产物 `target/Gastronomicon v1.1.6.jar`。
- shaded jar 体积 **2.19 MB → 277 KB**（外部库全部移除）。
- jar 内容审计（`jar tf`）：
  - `com/fasterxml/jackson` = **0**、`bstats` = **0**、`guizhan` = **0**、`javax/annotation/jsr305` = **0**、`com/*` = **0**（GSON/jackson/guava 等服务端库均不打包）。
  - 仅含 `io/github/schntgaispock/{gastronomicon, infinitylib}`（后者为 vendor 源码经 shade 重定向）+ resources。
- 全源码 import 审计：除服务端 API（`org.bukkit.*`/`io.papermc.*`/`net.kyori.*`/`io.github.thebusybiscuit.slimefun4.*`/`me.mrCookieSlime.*`/`com.google.gson.*`）外，无任何外部库引用。

## 结论

```
运行期依赖 = { Paper 1.21.11 服务端 API, Slimefun 4.1 (REF), 可选 SlimeHUD }
            ⊆ 「Papo 服务端提供的 API」 ✅
shaded jar = 仅插件自身代码（gastronomicon + vendor 的 infinitylib，已重定向）
外部库打包 = 0（jackson / bstats / guizhanlib / jsr305 全部移除）
匿名上报 = 无；更新检查 = 无
```
不会再出现「服务器缺某个前置库类」或「shaded 字节码与服务端 Slimefun 二进制不兼容」导致的加载失败。
