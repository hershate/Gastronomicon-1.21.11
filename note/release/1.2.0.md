# 1.2.0 — 性能优化（行为等价）

> 基于 `perf/optimization-rounds` 分支（自 `fix/remove-guizhanlib-runtime-dep` 切出），在 1.1.6 基础上的**纯性能优化**版本。
> **红线：安全性 / 稳定性 / 兼容性（行为等价）不破坏。** 无新功能、无 API 变更、无配置变更。
> 由 `/loop` 驱动的多轮优化，共 7 轮（Round 0–6），每轮含基准量化与报告。
> 完整基准方法论、Probe 结论、各轮报告见 [report/perf/PROGRESS.md](../report/perf/PROGRESS.md)。

## 方法论（诚实性）

- **基准分层**：经 [Probe](../../benchmark/src/io/github/schntgaispock/gastronomicon/benchmark/Probe.java) 实测，`isSimilar`/`getItemMeta`/`getByItem` 需 CraftServer/Slimefun 实例，**纯 JVM 不可运行**。
  - 纯 JVM 路径（NumberUtil / LootTable / Counter）→ 真实墙钟。
  - 耦合路径（配方匹配 / 合成路径）→ 同 JVM「忠实算法模型」+ 调用计数；绝对墙钟需服务端 Probe 校准。
- **同口径对比**：每轮 OLD vs NEW 在同一 JVM、同一 harness（[BenchmarkHarness](../../benchmark/src/io/github/schntgaispock/gastronomicon/benchmark/BenchmarkHarness.java)，5 预热 + 8 测量取最优）下测量。
- **行为等价**：每轮均论证或断言核对（Round 2 用 2000 万次采样核对分布逐位恒等；Round 5 用 `git stash` diff 核对 Counter 输出逐位一致；Round 3/4/6 用 `-ea` 断言）。

## 改动清单（按轮）

### Round 1 — RecipeComponent 缓存 SlimefunItem 解析（最热路径）⭐
- [SingleRecipeComponent](../../src/main/java/io/github/schntgaispock/gastronomicon/api/recipes/components/SingleRecipeComponent.java) / [GroupRecipeComponent](../../src/main/java/io/github/schntgaispock/gastronomicon/api/recipes/components/GroupRecipeComponent.java)：惰性缓存 `SlimefunItem.getByItem(不可变模板)`（volatile，异步 ticker 安全），`matches()` 不再每次解析；Group 改数组索引遍历。
- 消除「每个 ElectricKitchen 方块 × 每 tick × 每候选配方 × 每格原料」的重复 `getByItem`（含 ItemMeta 克隆/PDC 读）。
- 基准：`getByItem` 调用稳态 **100% 消除**；每 findRecipe 墙钟 **5.3–6.1×**。

### Round 2 — LootTable.generate（数组索引 + 整数随机 + 满桶跳过）
- [LootTable](../../src/main/java/io/github/schntgaispock/gastronomicon/api/loot/LootTable.java)：`drops` 改 `T[]`（数组索引）；`nextDouble()*tw` → `nextInt(tw)`（单次 `current()`，整数，别名法精确离散形式）；满概率桶（`prob>=tw`）跳过第二次随机。[EmptyItemLootTable](../../src/main/java/io/github/schntgaispock/gastronomicon/api/loot/EmptyItemLootTable.java) super 调用适配。
- 分布**逐位恒等**（2000 万次采样核对）；小表/均衡表 2.3–2.5×，大型各异表持平（永不回退）。

### Round 3 — NumberUtil / FoodEffect 数学与分配清理
- [NumberUtil.asRomanNumeral](../../src/main/java/io/github/schntgaispock/gastronomicon/util/NumberUtil.java)：4 个 `String[]` 查表提为 `static final`（1.25×）。
- [NumberUtil.roundToPrecision](../../src/main/java/io/github/schntgaispock/gastronomicon/util/NumberUtil.java)：`Math.pow(10,p)` → `switch` 常量（6.45×）。
- [FoodEffect.teleport](../../src/main/java/io/github/schntgaispock/gastronomicon/api/food/FoodEffect.java)：循环不变量 `Math.pow(r,3)` 提出循环 + int 乘替代（运行期，每次食用传送食物触发）。

### Round 4 — 合成路径分配（stream → loop）
- [GastroWorkstation](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/manual/GastroWorkstation.java)：原料/容器/工具收集由 `stream().mapToObj().toList()` 改 plain 循环 + `Arrays.asList`（去 3 流管线 + 2 ArrayList + 装箱）。[ElectricKitchen](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/automatic/ElectricKitchen.java) `getInputSlots()` 提 local 复用。craft-collect **3.36×**。

### Round 5 — Counter / 监听器 map 查找去重
- [Counter](../../src/main/java/io/github/schntgaispock/gastronomicon/util/collections/Counter.java)：`add/sub/get` 由 `containsKey+get+set` 链改单次 `get`+原地改（**4→1** map 查找）。
- [WildHarvestListener](../../src/main/java/io/github/schntgaispock/gastronomicon/core/listeners/WildHarvestListener.java)：`getDrops`/`getDropChance` map 查找去重。Counter.add **1.77×**。

### Round 6 — HuntingTrap.tick 分配 + 剩余路径巡检
- [HuntingTrap](../../src/main/java/io/github/schntgaispock/gastronomicon/core/slimefun/items/workstations/manual/HuntingTrap.java)：`b.getLocation()` 缓存复用（原 ~5 次/tick）+ `containsKey+get` 合并。**1.86×**（stub；真实 Location 更重）。

## 未闭合项（需服务端验证，不在本次范围）

`ElectricKitchen.findNextRecipe` 每 tick 的 `getItemMeta().hashCode()` 哈希（每方块每 tick 9 次 meta 克隆）。优化需缓存 per-slot 物品引用→哈希，前提：
1. `BlockMenu.getItemInSlot` 槽位未变时返回同一引用；
2. 槽位物品不会被原地改 meta。
确认后按 Round 1 volatile 惰性缓存范式实施。详见 [report/perf/PROGRESS.md](../report/perf/PROGRESS.md)。
